# PROMETHEUS · автотрейд — Telegram Mini App (UI-прототип)

Визуальный интерфейс автотрейд-бота. Данные моковые (`src/lib/mock.ts`),
бэкенда нет — прототип для проверки UX/UI и дизайн-системы.

```bash
npm install
npm run dev      # http://localhost:5178
```

## Два ограничения, о которых нужно знать

**SF Symbols нельзя.** Лицензия Apple разрешает использовать набор только в
приложениях для платформ Apple и прямо запрещает в веб-приложениях. Telegram
Mini App — это веб. Взяты `lucide-react`: та же геометрия штриха 1.5–2px, те же
метафоры, открытая лицензия ISC.

**Шрифт SF Pro тоже нельзя хостить.** Он лицензирован для разработки под Apple.
Поэтому в `theme.css` стоит системный стек: на iOS `-apple-system` разрешает
системе отдать настоящий San Francisco (это законно — шрифт берётся из ОС),
на Android подхватывается Roboto. Внешний файл шрифта не грузится вовсе.

## Связь с ботом

Настоящие данные приходят из автотрейд-бота (`autotrade_bot/webapi.py` в
репозитории `prometey`): открытые позиции, журнал закрытых сделок, настройки,
капитал счёта. Развёртывание — `autotrade_bot/deploy/MINIAPP.md`.

- **Адрес API приходит параметром `?api=`.** Бот подставляет в ссылку текущий
  адрес cloudflared-тоннеля, который меняется при каждом рестарте. Хардкод
  протухал бы вместе с тоннелем. Нет параметра — приложение работает на
  учебных данных, и говорит об этом плашкой.
- **Авторизация — подпись Telegram initData в заголовке**, не в строке
  запроса: там она осела бы в логах прокси.
- **Управление в приложении, но доступно владельцу счёта.** Право приходит с
  сервера полем `can` — фронт его не угадывает и не выводит из роли. Кнопки,
  недоступные пользователю, помечены замком и объясняют почему: молча не
  работающая кнопка хуже отсутствующей.
- **Результат действия берётся из ответа сервера, а не из своего представления
  о нём.** Значение могло быть отвергнуто проверкой диапазона, ордер — отбит
  биржей; экран обязан показать настоящее состояние. Отказ показывается
  текстом как есть: «не получилось» без причины заставляет гадать.
- **Непролившаяся лимитка — не позиция.** PnL по ней не считается вовсе: монет
  на счёте нет, терять и зарабатывать нечем. Считая её позицией, приложение
  брало цену сигнала за цену входа и показывало движение рынка как результат
  сделки, которой не было.
- **Билет веб-версии.** Вне Telegram подписи initData не существует, а ярлык с
  рабочего стола открывается именно в браузере. Билет приезжает параметром
  `?t=` и сохраняется в localStorage.

## Регистрация

Настоящая, в один шаг: **подтверждение номера телефона**.

- **Поля ввода номера нет вовсе.** Telegram показывает системное окно
  (`requestContact`) и сам присылает боту подтверждённый контакт. Набранный
  руками номер ничего не доказывает, а по номеру выдаются права
  администратора.
- **Экран регистрации не пропускается по одной подписи.** Подпись говорит лишь
  «это тот же Telegram-аккаунт»; пройденной регистрация считается, когда есть
  `phoneOk`. Иначе новый человек попадал бы сразу в кабинет, минуя
  единственный её шаг.
- **Контакт уходит боту отдельным сообщением**, и когда он дойдёт — неизвестно.
  Поэтому приложение ждёт появления отметки в профиле, а не верит ответу окна.
- **На старых клиентах** системного окна нет — тогда номер подтверждается в
  чате с ботом командой `/phone`. Тупика быть не должно.
- **История начинается с момента регистрации**, открытые позиции видны сразу:
  позиция существует прямо сейчас, а чужая история — нет.
- **Ключи биржи привязываются сами** в конце онбординга: бот торгует ключами
  из своего `.env`, вводить их второй раз незачем.

## Ярлык на рабочем столе — без Telegram

Значок открывает **самостоятельное веб-приложение**: своё окно на весь экран,
свой значок, никакого мессенджера вокруг. Способ Telegram (`addToHomeScreen`
из Bot API 8.0) здесь намеренно не используется — он ставит ярлык, который
открывает мини-апп ВНУТРИ Telegram.

- **Нужен манифест.** Без него iOS делает не приложение, а закладку: она
  открывается в Safari со всей адресной строкой. Плюс `apple-touch-icon` и
  `apple-mobile-web-app-capable` — иначе значок будет уменьшённым скриншотом.
- **Манифест персональный и собирается на лету** (`lib/pwa.ts`). Статический
  `start_url` запускал бы приложение по голому адресу — без билета и без
  адреса API, то есть каждый раз на демо-данных. Поэтому перед установкой
  `<link rel="manifest">` подменяется на blob с ПОЛНЫМ адресом текущей сессии.
- **Билет остаётся в адресной строке, пока приложение открыто во вкладке
  браузера,** и это осознанный размен. Адрес — ровно то, что «Добавить на
  экран Домой» запомнит в ярлыке: вычисти мы билет, ярлык открывался бы без
  доступа к счёту. У установленного приложения и внутри Telegram адресной
  строки нет вовсе, и там билет из адреса убирается.
  Полагаться на один localStorage нельзя: у установленного на iOS приложения
  хранилище своё, отдельное от Safari.
- **Android и десктопный Chrome** ставят приложение системным окном
  (`beforeinstallprompt` перехватывается, иначе предложение исчезает,
  не показавшись) — там инструкция не нужна вовсе.
- **Котировки идут мимо сервера**, прямо с Bybit по вебсокету: тик через опрос
  API приезжает с задержкой опроса и грузит бота работой, которую браузер
  делает сам. Сервер отдаёт геометрию сделки, биржа — цену.
- **Три разных состояния связи**, и путать их нельзя: демо (данных счёта нет),
  «доступ не ваш» (бот жив, но подпись не владельца — перезапрашивать
  бессмысленно, поэтому опрос прекращается) и «бот не отвечает» (цифры на
  экране последние известные).

Осталось учебным то, под что бэкенда нет вовсе: баланс сервиса, комиссия,
подписка, история платежей, лента новостей.

## Рыночные данные — настоящие

Цены, свечи и суточные изменения приходят с **публичного API Bybit**, без ключей
и без нашего сервера (`src/lib/market.ts`, хуки в `src/lib/useMarket.ts`).

- **Почему Bybit, а не агрегатор.** Бот исполняет ордера там же. Любой другой
  источник показывал бы соседний рынок: на мелких монетах расхождение доходит до
  процентов, и человек видел бы PnL, которого у него нет.
- **Два канала.** REST (`/v5/market/kline`, `/v5/market/tickers`) — история и
  первый снимок; WebSocket (`stream.bybit.com/v5/public/linear`) — тики и живая
  свеча. REST нужен обязательно: WS отдаёт только изменения, и без снимка первые
  секунды экран был бы пуст.
- **Дельты сливаются, а не заменяют.** В дельте Bybit может прийти один
  `lastPrice`; записав её целиком, мы обнулили бы суточный максимум и процент.
- **Разрыв связи — не событие рынка.** Переподключение с удвоением паузы до 20с,
  плюс подъём при возврате на вкладку. Пока связи нет, экран говорит «нет связи с
  биржей», а не показывает застывшую цену как текущую.
- **Подписки считаются по ссылкам.** Один тикер может быть нужен карточке и
  детали одновременно; отписка одного экрана не должна гасить второй.
- **Свечи переворачиваются.** Bybit отдаёт от новых к старым, график ждёт
  обратного порядка и на исходном молча рисует пустоту.
- **Точность оси — из самой цены.** С precision по умолчанию (2 знака) монета за
  $0.0143 превращается в прямую линию.

**Позиции собираются вокруг живой цены** (`mock.buildPosition`). В демо-данных
больше нет зашитых цен входа: DGAI с сентября ушла с 0.69 на 0.94, и позиция с
историческим входом показывала бы +36% несуществующей прибыли. Задаётся
геометрия — расстояние до стопа в процентах и сдвиг цены от входа в R, — а вход,
стоп, цель и размер считаются от котировки в момент запуска. Якорь ставится один
раз: пересобирай мы вход на каждом тике, цена вечно стояла бы на входе и PnL
замер бы на нуле.

**График свечной** — `lightweight-charts` с `CandlestickSeries`, четыре
таймфрейма (5м/15м/1ч/4ч), поверх линии входа, цели, стопа и безубытка.

**Навигация зависит от режима, и это не придирка.** Встроенный график живёт
внутри прокручиваемого экрана: вертикальное перетаскивание и колесо у него
отняты, иначе жест вверх вместо прокрутки двигал бы цену. **На весь экран**
(кнопка в углу графика) прокручивать нечего — включено всё, как в TradingView:
перетаскивание в обе стороны, щипок, колесо, растяжение осей перетаскиванием
(ось времени сжимает свечи, ось цены меняет вертикальный масштаб), двойное
касание оси — сброс, кинетическая инерция свайпа. Сверху — показания свечи под
курсором (O/H/L/C), и пишутся они **напрямую в DOM**: крестик двигается каждый
кадр жеста, и перерисовывать на это React нельзя.

**Сияние на карточке PnL** (`.aurora` в `theme.css`, компонент `ui/kit.tsx`).
Композиция взята с готового MIT-компонента CodeFronts «Animated Mesh Gradient
Blob Background» — несколько радиальных узлов плюс слой зерна. **Техника движения
заменена намеренно:** в оригинале анимируются координаты градиента через
`@property`, то есть весь размытый слой ПЕРЕРИСОВЫВАЕТСЯ каждый кадр. Здесь слои
статичные, а меняются только `transform` и `opacity` — их браузер отдаёт
композитору, поэтому после первой отрисовки ни JS, ни перерисовки нет вообще, и
анимация не спорит ни с прокруткой, ни с тиками цены. React монтирует разметку
один раз и больше её не трогает. Три узла с некратными периодами (19/26/31с),
чтобы не читался цикл; `prefers-reduced-motion` останавливает их в исходной позе.

Рассматривались и отклонены: `@mesh-gradient/core` (Apple-подобный, MIT, но
**WebGL** — кадровый цикл на GPU рядом с холстом графика) и Aceternity
`background-gradient-animation` (тянет Tailwind-классы с произвольными
значениями и JS-слежение за курсором).

Мок остаётся там, где данных без бэкенда взять неоткуда: история закрытых сделок,
кривая депозита, баланс, подписка, платежи, лента новостей.

## Дизайн-система

- **Токены** — `src/theme.css`. Тема ОДНА — тёмная (решение владельца 17.09.2026):
  светлого набора переменных в файле нет вовсе, иначе второй набор со временем
  разъезжается с первым. Оформление Telegram и системы игнорируется намеренно —
  `applyTheme()` настаивает на тёмном и перекрашивает шапку Telegram в чёрный,
  иначе над чёрным экраном висела бы белая полоса чужой шапки.
- **Только портрет.** Альбомная ориентация не поддерживается: на телефоне,
  положенном набок, под контент остаётся ~380px высоты, куда не помещаются ни
  шапка с крупным числом, ни панель вкладок. Вместо сломанного экрана —
  заглушка «переверните телефон» (`#rotate` в `index.html`, порог — ориентация
  + высота ≤520px + сенсорный ввод, чтобы не поймать десктоп).
- **Рамка телефона на десктопе.** На широком экране `#root` получает точные
  пропорции iPhone 15 Pro (393×852) и стоит по центру — смотреть прототип на
  1400px бессмысленно, пользователь видит его в окне шириной с телефон.
  `transform` на рамке не декоративный: он делает её containing block для
  `position: fixed` внутри, иначе панель вкладок, шторки, модалки и подсветка
  онбординга цеплялись бы за окно браузера и висели снаружи рамки. В Telegram
  рамки нет никогда (`inTelegram` в `main.tsx`).
- **Прокручивается `main`, а не страница** (`html,body,#root { overflow: hidden }`).
  Так панель вкладок остаётся приклеенной к низу, и так у рамки появляется
  точная высота, без которой пропорции не удержать. Побочное следствие: высоты
  шторок считаются в процентах от слоя, а не в `vh` — единицы окна внутри рамки
  означали бы высоту монитора.
- **Жидкое стекло** — класс `.glass`: `backdrop-filter: blur(22px) saturate(180%)`
  плюс градиентная рамка в 1px через `mask-composite` (обычный `border` одним
  цветом даёт плоский контур, стеклу нужен блик сверху и затухание снизу).
- **Подложка `.mesh`** — размытые цветные пятна под контентом. Без неё размывать
  нечего и «стекло» читается как обычная плашка.
- **Пружина одна на всё** — `SPRING` в `src/ui/kit.tsx`. Разные кривые в соседних
  элементах читаются как разное качество сборки.
- **Хаптика** — `src/lib/tg.ts`. На iOS это часть языка интерфейса.
- **Шкала кегля и радиусы** — по Apple HIG: body 17pt, largeTitle 34pt,
  карточка 22px, группа 16px, tabbar 52px + safe-area.

## Бизнес-модель в интерфейсе

- Комиссия **15%** с прибыльного PnL, **4%** при активной подписке.
- Подписка: 1 мес $20 · 3 мес $55 · 6 мес $95 · 12 мес $150. Автопродления нет.
- Расчёт раз в неделю, оплата вручную, USDT в сети Polygon (как в скринере).
- Не хватило средств → полноэкранное окно с QR, закрыть нельзя, новые сделки
  приостановлены (открытые позиции продолжают вестись).

## Что здесь ещё НЕ сделано

Бэкенда нет: авторизация принимает любой код, оплата подтверждается кнопкой,
котировки — случайное блуждание вокруг цены входа. График в детальном экране
рисуется по сгенерированному ряду, а не по свечам биржи.
